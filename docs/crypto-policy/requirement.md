# 需求：crypto-policy —— 国内数字货币政策/法规/案例雷达 + 法规库 + 解读草稿

> 状态：MVP 已落地（2026-11-08）｜模块目录：[`crypto-policy/`](../../crypto-policy/README.md)
> 关联：[设计文档](design.md) · [业务架构图](architecture.md) · [技术架构](technical.md) · [约定](../conventions.md)

## 1. 要解决什么问题（一句话）

国内虚拟货币政策「低频但高影响」：新文件/司法解释/典型案例一年只有十几到几十条，
但每一条都可能改变「现在到底适用什么规则」。现有 `crypto-news` 是 10 分钟新闻流，
抓不到「原文、效力层级、废止/替代关系、与旧规对比」。不做就会：错过 42 号文这类换规、
把媒体解读当成法规、事后才发现旧文已废止。

## 2. 边界：做什么 / 不做什么

### 做

- 盯 **T0/T1 权威源**（央行、外汇局、证监会、两高；后续扩地方金融办），只取**原文**；
- 规则门：去重、文档类型、主题、文号、发布/施行日、废止/替代关系、P0/P1/P2；
- 法规库：按文号建索引，记录状态（effective / pending / repealed）、版本、supersedes；
- 速报：P0 立即、P1 当日汇总，卡片只陈述事实 + 原文链接；
- 解读草稿：把 P0/P1 放进 `data/pending/`，由 DSH 任务生成解读（标注「AI 草稿，非法律意见」）；
- 周报（可选，手动按需）：只用于复盘「法规库/一周变化」；不排期、不固定推送。

### 不做

- 不做新闻流/情绪分析（交给 `crypto-news`）；
- 不做全自动法律意见直发；AI 只出草稿，必须标注、可人工复核；
- 不全文转载（只存正文供检索 + 原文链接）；
- 不抓裁判文书网全量（反爬/隐私），案例只取两高/案例库/处罚通报等公开典型；
- 不做交易、出入金、账户操作指引；
- **不做固定周期周报/日报**：本模块是事件驱动（有就发、没有就静默）；`weekly.py` 仅保留为手动工具，
  窗口内无变化默认静默，**不挂 launchd、不排期**，以后不因“周报没做”再立项。

## 3. 触发条件与等级

| 级别 | 条件 | 动作 |
|---|---|---|
| P0 | 法律/行政法规/司法解释；央行、证监会、外汇局正式文件且标题含虚拟货币/稳定币/RWA/挖矿；文件废止现行规定 | 立即推送 + 触发解读草稿 |
| P1 | 两高典型案例、外汇局处罚通报、地方重要文件；T0 规范性文件命中主题但非 P0 | 当日汇总推送 + 解读草稿 |
| P2 | 官方解读、答记者问、媒体评论、征求意见稿；正文命中但标题未命中 | 只归档（手动周报可见） |
| 忽略 | 与虚拟货币/稳定币/RWA/挖矿/外汇/洗钱无关 | 不进法规库 |

## 5. 验收标准（可测量）

1. `./crypto-policy/scripts/run.sh --fixtures tests/fixtures --dry-run` 退出码 0，
   输出含「新条目」，且 42 号文 fixture 被判为 `normative_doc` / `P0` / 文号 `银发〔2026〕42号`；
2. `python3 scripts/e2e.py` 返回 0（fixtures 回放 + 手动周报 dry-run）；
3. `make gate` 全绿；
4. 首次真实运行只做 baseline，不推送；之后无新条目时不推送；
5. `./scripts/run.sh --test` 能发出一条测试卡片；
6. 42 号文能自动把 `银发〔2021〕237号` 标记为 `repealed`（`data/index/policies.json`）。

## 6. 依赖的共享能力

- 已有：`crypto_core.http`（抓取）、`crypto_core.store`（原子写）、`crypto_core.text`（清洗/哈希）、
  `crypto_core.timeutil`（时间/静默时段）、`crypto_core.notify`（Telegram）、`tools/render_launchd.py`（调度）。
- 需要新增：无。AI 解读复用 DSH 定时任务，不在模块内直连模型 API。

## 7. 风险与对策

| 风险 | 对策 |
|---|---|
| 官方站反爬/改版 | 多源 + 列表选择器配置化 + 单源失败隔离 + `r.jina.ai` 兜底 |
| 规则漏检（标题没写关键词） | P0 源全量保留进索引；周度抽检；后续加灰区 AI 分诊 |
| AI 解读幻觉/越权 | 强制引用原文、标注「草稿/非法律意见」、只对 P0/P1、人工复核 |
| 低频导致遗忘 | 不做心跳/平安消息；用 launchd 日志和 `state/source-*.json` 的 `last_check` 判断源是否正常，必要时手动复盘 |
| 版权 | 只存正文供检索、卡片给原文链接，不全文转载 |
