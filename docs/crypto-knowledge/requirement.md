# 需求：crypto-knowledge —— 每日碎片化学习推送

> 状态：**已实现并运行**（2026-11-09）｜模块目录：[`crypto-knowledge/`](../../crypto-knowledge/README.md)
> 关联：[个人学习方案](../crypto-learning-plan.md) · [设计](design.md) · [业务架构](architecture.md) · [技术架构](technical.md)
> 合规：研究/学习定位；不交易、不出入金、不提供投资建议；实践只在测试网与公开只读数据上完成。

## 1. 要解决什么问题（一句话）

把「系统学加密知识」拆成**每天 4 条：3 节 10–15 分钟课程 + 21:00 回顾与总结（周日为本周回顾）**，按由浅入深的固定顺序推送，并用间隔复习对抗遗忘；让长期坚持不依赖意志力。

## 2. 设计约束（2026-11-09）

| 项 | 结论 |
|---|---|
| 周期 | **长期学习**，每周 3–4 小时或更少，强调「长期坚持 + 碎片化时间」 |
| 形式 | 每天 **13:00 / 19:00 / 21:00 / 23:00** 各一条，**内容各不相同**；吃饭、通勤、睡前都能看 |
| 内容 | 理论 / 实践 / 概念与专业术语都要；**由浅入深，先基础再深入** |
| 主线 | BTC / ETH 为主轴，BNB 作交易所生态样本；SOL 等只作对照 |
| 产物位置 | 模块代码在本仓库 `crypto-knowledge/`；学习笔记放**本地** `learning/`（不入库） |
| 自动化 | 定时推送，不需要人工触发 |

## 3. 做什么 / 不做什么

### 做

- 每天四条**不同**内容：13:00 概念课、19:00 理论/实践课、21:00 今日回顾与总结（**周日升级为本周回顾**）、23:00 主动回忆复盘。
- 160 条课程内容，按 4 个阶段递进：基础 → 机制 → 市场 → 监管/安全/研究方法。
- 间隔复习：条目在第 1/3/7/14/30/60 天再次出现；23:00 用「问题 + 可点开答案」自测。
- 状态可恢复：同日同时段去重、错过时段跳过、内容池耗尽自动转复习模式。
- 全部产物落盘：`data/reports/<date>.md` 存档当天三条消息。

### 不做

- 不交易、不出入金、不接交易所账户/API key/私钥；不提供买卖点位、杠杆、合约操作指引。
- 不推价格、收益、预测；不做「必涨/必跌/目标价」。
- 不接付费数据源、不调外部 LLM、不新增第三方依赖。
- 不替代系统学习：它是「碎片输入 + 复习」，完整路线仍以学习方案为准。

## 4. 输出与频率

| 时段 | 内容 | 时长 | 来源 | 送达 |
|---|---|---|---|---|
| 13:00 | 概念课：6 节 + 2–3 道自测 | 10–12 分钟 | 概念轨道游标 | Telegram |
| 19:00 | 理论课（5–6 节）或实践课（5 节） | 12–15 分钟 | 课程轨道游标 | Telegram |
| 21:00 | 回顾与总结：今日课程 + 每条 2 个要点 + 进度 + 一句话总结 + 明日预告；**周日为本周回顾**（本周课程/关键要点/本周数据/本周自测/下周预告） | 约 8 / 10 分钟 | 当日 sent + state | Telegram |
| 23:00 | 复盘课：今日 2 条各 2 题主动回忆 + 间隔复习 + 综合思考 + 明日预告 | 约 12 分钟 | SRS + 当日 sent | Telegram（正常通知） |

## 5. 验收标准（可测量）

1. `python3 crypto-knowledge/scripts/check_content.py` → 160 条、四阶段分布 40/40/40/40、校验通过。
2. `python3 -m unittest discover -s crypto-knowledge/tests -v` → 全绿、**断网可跑**；每条课程 `minutes` 10–15、正文 800–1800 字、概念/理论至少 2 道自测题。
3. `--dry-run` 四个时段均能渲染出 ≤ 3800 字的 Telegram HTML，且内容互不重复。
4. 同一天同一时段重复执行只发送一次；`--force` 重发同一条且不推进游标。
5. launchd 安装后 `make launchd module=crypto-knowledge action=status` 显示已加载，四个触发时间生效。
6. 发送成功后 `data/state/progress.json` 游标推进、条目 `next_due` 正确、`data/reports/<date>.md` 有存档。
7. 21:00 回顾总结包含今日课程、每条 2 个关键要点、进度（第 N 天 / 已学 / 待复习 / 连续天数）、一句话总结与明日预告；且**不推进 SRS**。
8. 周日 21:00 自动渲染本周回顾（本周课程 / 关键要点 / 本周数据 / 本周自测 / 下周预告，约 10 分钟）；`--weekly` 可在任意日期强制预览。

## 7. 风险与对策

| 风险 | 对策 |
|---|---|
| 内容错误误导 | 内容 schema 强校验 + 写作规则（官方一手来源、不写价格/预测）+ 事实按 2026-02-06 42 号文口径 |
| 夜间打扰 | 设计约束不静默、不延迟：所有消息正常通知；Mac 休眠错过的时段在下次运行时补发 |
| Mac 休眠错过 | 错过时段直接跳过；不补发、不刷屏 |
| Telegram 发送失败 | 不推进状态，下一轮重试同一条；错误写日志 |
| 内容池耗尽 | 自动转复习模式，优先循环实践条目 |
| 学习断档 | 23:00 的 SRS 会把旧条目拉回来；状态文件持久化 |
