# ADR 0010：运行时从 Python 3.9 升级到 3.12

- 状态：进行中（第一阶段：代码与 CI 同时兼容 3.9 / 3.12）
- 日期：2026-11-16

## 背景

线上 `.venv` 基于 macOS CommandLineTools 自带的 Python 3.9.6。3.9 已于 2025-10 停止安全更新，且 CLT 的 Python 随 Xcode 更新变化，不受本仓库控制。
所有 launchd 任务都经 `.venv/bin/python` 运行（模块 `collect.sh` 通过 `tools/lib/module_round.sh` 的 `PY`，watchdog 的 plist 直接指向它），因此升级的切换点只有 `.venv` 一处。

## 决策

分两阶段：

1. **兼容期（本 ADR 首个 PR）**：CI gate 用 3.9 和 3.12 两个版本各跑一遍；修复 3.12 下才暴露的问题。代码继续以 3.9 语法为下限（`pyproject` 的 `target-version = py39` 不变）。
2. **切换**：用带 `time.tzset` 的 3.12 解释器（见下）新建 `.venv`，与旧 `.venv` 原子互换（目录改名），盯一轮各模块 launchd 轮次与 watchdog；异常时改名换回即回退。稳定一周后把下限提到 3.12（`requires-python`、`target-version`、AGENTS/conventions 文案），CI 去掉 3.9。

## 解释器选择

本机现有的 `~/.local/bin/python3.12` 是 uv 管理的独立构建，**没有 `time.tzset`**。`crypto_core.timeutil.apply_timezone` 遇到这种情况会退化为宿主时区，不会报错，但配置的时区会悄悄失效。目前各模块 `app.yaml` 都没配 `timezone`，所以对线上暂时没有影响，只是隐患。
切换时优先用带 `tzset` 的构建（Homebrew `python@3.12` 或 python.org 安装包）；需要在本机安装软件，由用户确认。

## 已发现的 3.12 差异

- `libs/crypto_core/tests/test_module_helpers.py` 在缺 `tzset` 的构建上 `mock.patch.object(time, "tzset")` 报 AttributeError → 改为 `create=True`，并补「缺 tzset 时退化」的用例。
- 其余 22 个 gate 步骤（全部单测、各模块 e2e、ruff、复杂度棘轮）在 3.12 下直接通过。
