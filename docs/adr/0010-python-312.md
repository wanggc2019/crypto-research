# ADR 0010：运行时从 Python 3.9 升级到 3.12

- 状态：已完成（2026-11-16 线上切到 3.12.10；同日因引入 Anthropic SDK（需 ≥3.10，见 ADR 0011）提前收尾：下限 3.12、CI 只跑 3.12、删除 `.venv-py39`）
- 日期：2026-11-16

## 背景

线上 `.venv` 基于 macOS CommandLineTools 自带的 Python 3.9.6。3.9 已于 2025-10 停止安全更新，且 CLT 的 Python 随 Xcode 更新变化，不受本仓库控制。
所有 launchd 任务都经 `.venv/bin/python` 运行（模块 `collect.sh` 通过 `tools/lib/module_round.sh` 的 `PY`，watchdog 的 plist 直接指向它），因此升级的切换点只有 `.venv` 一处。

## 决策

分两阶段：

1. **兼容期（本 ADR 首个 PR）**：CI gate 用 3.9 和 3.12 两个版本各跑一遍；修复 3.12 下才暴露的问题。代码继续以 3.9 语法为下限（`pyproject` 的 `target-version = py39` 不变）。
2. **切换**：用带 `time.tzset` 的 3.12 解释器（见下）新建 `.venv`，与旧 `.venv` 原子互换（目录改名），盯一轮各模块 launchd 轮次与 watchdog；异常时改名换回即回退。稳定一周后把下限提到 3.12（`requires-python`、`target-version`、AGENTS/conventions 文案），CI 去掉 3.9。

## 解释器选择

本机现有的 `~/.local/bin/python3.12` 是 uv 管理的独立构建，**没有 `time.tzset`**。`crypto_core.timeutil.apply_timezone` 遇到这种情况会退化为宿主时区，不会报错，但配置的时区会悄悄失效。目前各模块 `app.yaml` 都没配 `timezone`，所以对线上暂时没有影响，只是隐患。
切换时优先用带 `tzset` 的构建。Homebrew 已把 Intel macOS 列为 Tier 3、不再出 bottle（需源码编译多个依赖），因此改用 **python.org 官方安装包 3.12.10**（3.12 系列最后一个带 macOS 安装包的版本），装在 `/Library/Frameworks/Python.framework/Versions/3.12/`，不影响系统自带 3.9。`make setup` 优先使用它（`SETUP_PYTHON` 可覆盖）。

## 已发现的 3.12 差异

- `libs/crypto_core/tests/test_module_helpers.py` 在缺 `tzset` 的构建上 `mock.patch.object(time, "tzset")` 报 AttributeError → 改为 `create=True`，并补「缺 tzset 时退化」的用例。
- 其余 22 个 gate 步骤（全部单测、各模块 e2e、ruff、复杂度棘轮）在 3.12 下直接通过。
- crypto-analyst 的 `utcnow()` / `utcfromtimestamp()`（3.12 起弃用，会往日志写警告）改为 `now(timezone.utc)` / `fromtimestamp(..., timezone.utc)`，日期字符串不变。顺带修正 `macro.fetch_dvol` 的查询起点：旧写法对不带时区的 UTC 时间调 `.timestamp()`，会被当作本地时间解释，偏移量等于本地时区与 UTC 的差（本机 +04:00 时偏 4 小时）。

## 切换记录（2026-11-16）

1. 用 python.org 3.12.10 在副本工作树建 venv（PyYAML 6.0.3、ruff 0.17.4，与旧 venv 同版本），`tools/gate.py` 23 步全绿；
2. **第一次切换（14:08:52）失败，14:12:10 回退**：python.org 构建的 OpenSSL 只认 `…/Versions/3.12/etc/openssl/cert.pem`，安装后该文件不存在（需另跑 `Install Certificates.command`），所有 HTTPS 请求 `CERTIFICATE_VERIFY_FAILED`。gate 全部离线，没覆盖到。影响：price 3 轮 rc=3、Telegram 发送同样失败（无消息送出）；watchdog 14:13 如实推了 1 条失败告警；price 重试队列里因此产生的「行情全源不可用」P0 已手工移除，未送达；
3. 临时修复：把该路径链接到 `/etc/ssl/cert.pem`；交易所/Telegram/Jina/DeepSeek 握手正常，`tools/gate.py --only network --strict-network` 9/9（但见第 6 条）；
4. **第二次切换（14:18:29）成功**：price / news / onchain / x-kol 切换后各轮 rc=0，日志无证书错误、Traceback、DeprecationWarning；
5. watchdog 是唯一由 launchd 直接 exec `.venv/bin/python` 的任务（其余 plist 是 `/bin/bash`）。launchd 记录的启动约束（LWCR）绑定旧的 Apple 签名解释器，换成 PSF 签名后被 `OS_REASON_CODESIGNING` 杀掉（退出 -9，漏 1 轮）。`.venv/bin/python tools/watchdog.py --install` 重新注册后恢复（14:24:52 rc=0）；
6. **`/etc/ssl/cert.pem` 不够**：15:16 起 crypto-policy 的 `ecb_press` 每轮 `unable to get local issuer certificate`（rc=1）。该文件只有 123 张根证书，缺 ECB 证书链需要的 Sectigo Public Server Authentication Root E46；3.9 能过，推测是 Apple 构建的 SSL 库在文件找不到时会回退到 macOS 钥匙串，python.org 构建不会。对全仓配置里的 82 个 HTTPS 主机做握手扫描：系统文件 1 个证书失败（ECB），certifi / macOS 系统根证书导出均 0 失败。18:30 改为 python.org 推荐做法：`python3.12 -m pip install --upgrade certifi`（装在 framework，不在 `.venv`），`etc/openssl/cert.pem` → `certifi/cacert.pem`（与 `Install Certificates.command` 等价）。

### CA 证书维护

- 证书来源：framework 里的 certifi（Mozilla 根证书库），**不随 macOS 更新**；每季度或遇到新的 `CERTIFICATE_VERIFY_FAILED` 时执行
  `/Library/Frameworks/Python.framework/Versions/3.12/bin/python3.12 -m pip install --upgrade certifi`（链接指向固定路径，升级后自动生效）。

### 以后切换 / 回退的检查清单

- 新解释器先过 `tools/check_ca.py`（`make setup` 会自动跑，离线检查 CA 文件存在）、`tools/gate.py` **和** `--only network --strict-network`（离线 gate 测不到握手）；
- 再对全仓配置里的 HTTPS 主机做一次握手对比（新旧解释器结果应一致；只看 price 冒烟漏掉了 ECB）；
- 等所有轮次空闲再改名（同卷 `mv`，原子）；改名后 `pip install --force-reinstall --no-deps` 重写 `bin/` 脚本 shebang；
- **改名后立即** `.venv/bin/python tools/watchdog.py --install`，并用 `launchctl print gui/$(id -u)/com.crypto-research.watchdog` 看 `last exit code = 0`；
- 盯下一轮 price（每分钟）rc；非 0 立即回退。

回退：收尾后不再保留 3.9 venv（代码已依赖 anthropic SDK，3.9 装不上）；`.venv` 损坏时用 `rm -rf .venv && make setup && .venv/bin/python tools/watchdog.py --install` 重建。`.venv-*/` 仍在 `.gitignore` 里，供以后换解释器时临时备份。
