# 课程内容格式规范（v2 · 每条 10–15 分钟）

> 本目录是 `crypto-knowledge` 的内容库。**只放内容，不放代码**。
> 一个文件 = 一个阶段；`stage1.yaml` … `stage4.yaml`，按阶段顺序拼接成完整课程。
> 引擎按 `stage` → `order` 排序；每天 13:00 取 1 条 `concept`，19:00 取 1 条 `lesson`（`theory` / `practice`），23:00 用当天内容 + 到期条目组织**复盘课**。
>
> **v2 变化**：每条从 3–5 分钟扩到 **10–15 分钟**；`minutes` 改 10–15；`sections` 4–6 节；`quiz` 改为 **2–3 道题的列表**（复盘课要用）。

## 1. 文件结构

```yaml
schema_version: 1
stage: 1
title: 基础：货币、账本、密码学与比特币
weeks: "W1–W4"
items:
  - id: c101
    ...
```

| 字段 | 必填 | 说明 |
|---|---|---|
| `schema_version` | 是 | 固定 `1` |
| `stage` | 是 | 1–4，与文件名一致 |
| `title` | 是 | 阶段标题，用于消息页眉 |
| `weeks` | 否 | 对应学习计划周次，如 `"W1–W4"` |
| `items` | 是 | 条目列表，见下 |

## 2. 条目字段（v2）

| 字段 | 必填 | 约束 |
|---|---|---|
| `id` | 是 | **全局唯一**。概念 `c<stage><两位序号>`（如 `c101`）；理论 `t<stage><序号>`（如 `t201`）；实践 `p<stage><序号>`（如 `p308`） |
| `type` | 是 | `concept` / `theory` / `practice` |
| `stage` | 是 | 1–4，与文件一致 |
| `order` | 是 | 阶段内顺序，整数。概念 1–20；课程（理论/实践）1–20，按教学顺序交错编排 |
| `title` | 是 | 标题，≤ 24 个汉字，不带句号 |
| `en` | 否 | 英文名/缩写，≤ 40 字符 |
| `minutes` | 是 | **10–15**（概念 10–12，理论 12–15，实践 10–15） |
| `tags` | 否 | 1–3 个小写标签 |
| `sections` | 是 | **4–6 节**，每节 `{h, p}`：`h` ≤ 10 字，`p` 50–420 字 |
| `quiz` | 是 | **2–3 道题的列表**（实践 1–2 道）：`[{q,a}, ...]`；`q` 8–60 字，`a` 20–200 字 |
| `sources` | 否 | 0–2 个**真实可访问**的 URL；优先官方一手文档 |

> 单条正文（`sections` + `quiz` 的答案）控制在 **900–1600 字**，对应 10–15 分钟：精读 5–7 分钟、例子 3 分钟、自测 2 分钟、记笔记 1–2 分钟。不够深就补机制、数字、反例；不要靠重复凑字数。

## 3. 三种条目怎么写（v2）

### concept（概念课，13:00，10–12 分钟）

固定六节：`一句话` / `为什么重要` / `核心机制` / `例子` / `常见误解` / `边界与代价`。要求：定义准确、给出机制与反例、说明适用边界。**2–3 道自测题**。

```yaml
- id: c101
  type: concept
  stage: 1
  order: 1
  title: 账本
  en: Ledger
  minutes: 11
  tags: [basics, ledger]
  sections:
    - h: 一句话
      p: 账本（ledger）记录“谁拥有什么、发生过什么”。货币本质上是一套被多方共同承认的记账系统，而不是一张纸或一块金属。
    - h: 为什么重要
      p: 区块链不是“更快的数据库”，而是让互不信任的多方共用同一本账的机制。先有账本问题，共识、UTXO、Gas 这些设计才接得上；否则你会把区块链当成一种更贵的数据库。
    - h: 核心机制
      p: 任何账本都要回答三件事：记录什么、谁来记、冲突时听谁的。中心化账本用银行/清算所回答第三个问题；区块链把“听谁的”交给公开规则和多数算力/质押，代价是速度、成本和最终性延迟。
    - h: 例子
      p: 银行转账在你的账户里是一笔分录，在银行资产负债表上是负债的转移；跨行还要经过清算系统。账本并不“搬钱”，它只是改记录。区块链把这套记录公开给所有节点，让改记录必须付出全网验证的成本。
    - h: 常见误解
      p: 把不可篡改当成账本的默认属性。银行数据库随时可改，成本极低；不可篡改只在需要多方互相核对、且有人可能作恶时才值得付出冗余、延迟与手续费。
    - h: 边界与代价
      p: 当参与方本来就互相信任（公司内部、单一平台），用区块链反而更慢更贵；它的价值集中在“跨主体、低信任、需要共同审计”的场景。
  quiz:
    - q: 如果只有一个人记账，还需要区块链吗？
      a: 基本不需要。区块链的价值来自多方互不信任又要共用记录；单人记账用普通数据库更快、更便宜，改错也更容易。
    - q: 账本要回答的三个问题是什么？
      a: 记录什么、谁来记、冲突时听谁的。区块链的创新主要在第三个问题上：用公开规则与算力/质押替代中心机构仲裁。
    - q: 为什么“不可篡改”是有代价的？
      a: 它要求全网重复存储与验证、出块排队确认，换来的是无需信任中间人；在互信场景里这些成本没有对应收益。
  sources:
    - https://bitcoin.org/bitcoin.pdf
```

### theory（理论课，19:00，12–15 分钟）

5–6 节，建议：`核心机制` / `关键细节` / `例子（带数字或流程）` / `对比或演进` / `代价与边界` / `常见误读`。必须至少有一个具体例子，不能只讲结论。**2–3 道自测题**。

### practice（实践课，19:00，10–15 分钟）

固定五节：`目标` / `准备` / `步骤` / `验收` / `安全与常见坑`。**必须在测试网、公开数据或只读范围内完成，不涉及真实资金、交易、出入金。** 步骤要能照着做，验收要可检查。**1–2 道自测题**。

## 4. 写作规则（v2）

1. **准确优先**：只写教科书级、能被官方文档支持的事实；不确定的数字/时点，改成不需要该数字的表述，或标“（以官方文档为准）”。**绝不编造**。
2. **讲机制、讲代价、讲边界**：每条至少回答“它解决什么问题、付出什么代价、什么情况下不适用”。
3. **例子要具体**：给流程、数字量级、对比或反例；不写“众所周知”。
4. **不写价格、不写收益、不写预测**；不出现“必涨/必跌/目标价/稳赚”。
5. **不提供交易指引**：不写开户、出入金、买卖点位、杠杆、合约操作。
6. **合规**：涉及中国内地监管时，以 2026-02-06 八部门 42 号文为准（境内虚拟货币业务一律禁止；RWA 代币化分类监管），不沿用已废止的 924 通知表述。
7. **术语首次出现给英文**，之后用中文。
8. **每条只讲清一个点**，但要把这个点讲透；宁可深，不要散。
9. sources 只允许真实存在的官方/权威域名，例如：`bitcoin.org`、`ethereum.org`、`eips.ethereum.org`、`ethbeat.org`、`defillama.com`、`dune.com`、`glassnode.com`、`mempool.space`、`etherscan.io`、`occ.treas.gov`、`sec.gov`、`hkma.gov.hk`、`policy.mofcom.gov.cn`、`github.com/bitcoinbook`、`github.com/ethereumbook`。**不确定就不要写 sources**，不要编造深链接。
